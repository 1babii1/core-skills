# Lightweight CRM and Follow-up

## Start small

For a solo developer, use a local Markdown table, CSV, or simple spreadsheet until real volume justifies a CRM platform. The system must help choose the next action, not become a customization project.

Suggested stages:

`New → Qualifying → Conversation → Discovery → Estimating → Proposal → Agreement → Won / Lost → Delivery → Closed → Follow-up`

Define entry and exit evidence for each stage. Do not advance a deal because it “feels promising.”

## Minimum opportunity record

| Field | Purpose |
| --- | --- |
| Opportunity ID | Stable non-sensitive identifier |
| Client/organization | Professional identity only |
| Source | Channel or referral provenance |
| Requested outcome | One-sentence problem/result |
| Stage | Current evidence-backed state |
| Fit and risks | Strong/mixed/weak/unknown with reasons |
| Value | Quoted or estimated amount, currency, and status |
| Decision-maker | Known role/person or unknown |
| Last meaningful interaction | Date and factual summary |
| Next action | Concrete mutual or owner action |
| Next-action owner | User, client, or named stakeholder |
| Next-action date | Follow-up or decision date |
| Open questions | Facts blocking progress |
| Proposal/estimate version | Link or identifier |
| Outcome | Won/lost/declined and evidence-based reason |
| Revisit condition | Date or trigger when appropriate |

Do not store secrets, payment-card data, identity documents, sensitive personal traits, private scraped data, or unnecessary conversation content.

## Pipeline hygiene

Review active opportunities at a cadence proportional to volume:

- Is the stage supported by evidence?
- Is there a concrete next action, owner, and date?
- Is the last interaction accurately recorded?
- Is the proposal/estimate version current?
- Did scope, price, deadline, or decision process change?
- Is the opportunity waiting on the user, client, or third party?
- Should it advance, remain, return to discovery, pause, close lost, or be declined?

Stale does not automatically mean “send another message.” It may mean the opportunity is not important, not qualified, or should be closed.

## Follow-up rules

A useful follow-up:

- refers to the actual prior context;
- adds a decision, answer, artifact, or clear question;
- respects the agreed timing;
- makes stopping easy;
- does not pretend urgency or entitlement to a reply.

After a reasonable number of unanswered attempts appropriate to the relationship and channel, close or pause the opportunity. Record a revisit trigger instead of maintaining a fantasy pipeline.

## Forecasting

For a first-order pipeline, report:

- count and value by stage;
- confirmed quotes versus rough potential;
- next actions due;
- stalled or blocked opportunities;
- acquisition time spent;
- wins, losses, and reasons.

Do not assign standard stage probabilities and call the result expected revenue. Use historical conversion only after the sample and process are sufficiently comparable; show sample size, period, and uncertainty.

## External systems

Before creating or updating an external CRM:

1. confirm the exact account/workspace and records;
2. show material field mapping and overwrite behavior;
3. detect duplicates;
4. minimize personal data;
5. obtain authorization for the external write;
6. verify the result without exposing sensitive fields.
