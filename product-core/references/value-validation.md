# Value Validation

## Match test to risk

| Risk | Useful early tests |
|---|---|
| Problem | Mom Test interviews, workflow observation, review/support analysis |
| Demand | commitment ask, waitlist with qualified action, preorder, paid pilot, LOI |
| Usability | task prototype, moderated usability test |
| Feasibility | technical spike, API/data proof, capacity benchmark |
| Viability | pricing conversation anchored in current spend, unit economics, sales/support/legal review |
| Distribution | outreach response, channel smoke test, acquisition-cost probe |
| Ethics/compliance | threat/impact assessment and specialist review |

Other useful forms include concierge delivery, Wizard of Oz, fake door with transparent follow-up, landing-page smoke test, clickable prototype, manual service, and narrow beta.

## Test contract

Define before running:

- one assumption;
- target segment and recruitment channel;
- observable behavior;
- smallest credible test;
- pass, fail, and inconclusive thresholds;
- sample/traffic limitation;
- guardrails and ethical constraints;
- duration and owner;
- decision each outcome triggers;
- disposal/cleanup plan for temporary artifacts and participant data.

Choose evidence that could prove the team wrong. A polished prototype, waitlist count, or positive survey is not validation unless it changes a real decision and the signal matches the risk.

Use A/B testing only when randomization, stable instrumentation, adequate exposure, meaningful effect size, and interference control are credible. For low traffic, prefer qualitative behavioral tests, sequential commitments, or a staged rollout without pretending they provide statistical proof.
